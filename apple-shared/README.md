# Shared Apple companion layer

The native macOS/iOS projects compile these files directly. There are no Swift package, C, JNI, telemetry or network-install dependencies. `generate-projects.py` deterministically generates both checked-in Xcode projects and shared schemes using the Python standard library; it does not build or test them.

## Security and persistence

- QR parsing rejects duplicate keys, malformed fingerprints and non-local destination forms. Prefer `fp_sha256` (full SHA-256 certificate DER); legacy `fp` supports the existing 16-hex prefix. Bootstrap sends only an unauthenticated `GET /pair/ca` in a dedicated no-cookie/no-redirect session. The returned CA must match the QR before any token is sent.
- Every token-bearing/API connection uses TLS 1.3, the pinned CA as its sole trust anchor, server TLS certificate evaluation, expiry/signature/EKU checks and logical server name `homehub.local`. That name matches the Hub certificate SAN; DHCP LAN addresses intentionally are not certificate SANs. Trust evaluation cannot fetch certificates externally. Redirects and authentication fallbacks are denied.
- P-256 private keys are permanent device-only Keychain keys; they are never exported. This implementation uses Keychain-backed software keys, not a promise that every supported Mac/iPhone has Secure Enclave storage. PKCS#10 requests are signed through Security.framework. Issued leaves must match the generated public key and CA before installation. Trust/leaf metadata also lives in the device-only Keychain. Share extensions have no credential access.
- Expiring certificates renew before transfers/Photos discovery. If a Hub revokes the prior serial before its renewal response reaches durable client storage, re-pairing is necessary; server-side overlap/recovery is needed to eliminate that protocol failure window.
- Queue files are independent atomic JSON records and private staged copies, fsynced with their parent directory before acceptance. Share provider data is copied while its temporary URL is still valid. No source bookmark or provider lifetime is used as the durable source. A damaged record is reported and preserved; the queue is never replaced with an empty array.
- Uploads stream a dependency-free BLAKE3 tree hash, resume from Hub verified chunk ranges, check completion hash/size and save done before removing only the private staging copy. Backoff survives restarts. User originals are never moved/deleted. User-selected and relay downloads persist a private cache in 4 MiB HTTP ranges, validate each Content-Range/size, resume at full range boundaries and install only after fresh whole-file BLAKE3 verification. They never replace an existing destination.

## Validation status

Implementation and project generation only. No build, formatting, static checks or test execution was run during these phases, per the deferred-test instruction. XCTest sources cover published BLAKE3 vectors, incremental tree boundaries, QR trust/destination rejection, provider-source loss/restart persistence, corrupt queue preservation and verification of the persistent-key CSR signature. Native signing, device Keychain/mTLS behavior, iOS extension lifecycle and physical interrupted-transfer cases require the later full validation gate.

Apple references used for SDK behavior: [sole trust anchors](https://developer.apple.com/documentation/security/sectrustsetanchorcertificatesonly(_:_:)), [trust configuration](https://developer.apple.com/documentation/security/configuring-a-trust), [Photos resource export](https://developer.apple.com/documentation/photos/phassetresourcemanager/writedata(for:tofile:options:completionhandler:)), [background connectivity constraints](https://developer.apple.com/documentation/backgroundtasks/bgprocessingtaskrequest/requiresnetworkconnectivity).
