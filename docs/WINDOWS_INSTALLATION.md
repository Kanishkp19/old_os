# Windows Home Hub installation and recovery

The canonical installer is `installer/homehub.iss` (Inno Setup 6). The WiX file is an unmaintained alternative in this release. Build on a clean x64 Windows environment with Rust/MSVC, Node.js, Inno Setup 6, PowerShell and the official x64 Evergreen WebView2 standalone installer. Place the latter at `installer/deps/MicrosoftEdgeWebView2RuntimeInstallerX64.exe`; `installer/release/prepare.ps1` rejects a missing file or an invalid Microsoft Authenticode signature. It builds all Rust binaries, the Svelte dashboard and Tauri shell, stages them, and invokes ISCC. The installer output is `installer/out/HomeHubSetup-0.1.0.exe`. Set `HOMEHUB_SIGN_PFX` and `HOMEHUB_SIGN_PASSWORD` only in the release environment to sign Home Hub binaries and the installer. Never commit certificates or signing passwords.

Install as administrator and choose the Windows account that will own the Hub. If UAC uses a different administrator account, enter the everyday account as `COMPUTER\user` or `DOMAIN\user`. Upgrades preserve the existing owner SID and refuse to silently transfer administration to another account. The service runs as LocalSystem; `hh-session` and the single `hh-tray` start at that owner's logon with limited privileges. The desktop opens as a normal user. Firewall rules permit only Private-profile local-subnet access to the Hub API, pairing and discovery ports and the session helper's video UDP. Port 47801 is loopback-only and has no inbound firewall rule.

The installer stops the old service, copies its database/WAL/configuration and executable files to `%ProgramData%\HomeHub\upgrade-backup-*`, then replaces application binaries. It registers the service and login task, starts the service, and retains the backup. `hh-service --backup-database <unused-destination> --data-dir <data-dir>` also creates a consistent online SQLite snapshot for an operator-triggered backup. To recover a failed upgrade, run `installer/runtime/restore-upgrade.ps1 -AppDir <installation-folder> -DataDir <data-folder>` as administrator after confirming the saved backup. That script stops the service, saves the current database and configuration in `failed-upgrade-*`, restores the previous binaries and database together, then restarts the service. Review any data written after the upgrade before choosing rollback; the newer database remains available in that saved folder.

Uninstall unregisters the service, login task and firewall rules. It keeps the Hub database, CA identity, library, second-copy drive and per-user private Notes/playlists/browser state by default. To remove those later, use an explicit, reviewed cleanup on the intended machine after a verified backup.

The macOS development host cannot compile, install or verify this Windows package. Record the actual installer, reboot, login, repair, rollback and uninstall results in `docs/WINDOWS_VALIDATION.md` on the physical Windows laptop before release. Offline core Hub operations work without internet; only the Browser, YouTube and owner-enabled update checks need internet.
